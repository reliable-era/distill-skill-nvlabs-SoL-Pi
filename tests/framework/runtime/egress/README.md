# Provider-only actor egress prototype

Mock-tested Docker network isolation; no model requests or credentials used. Run `python tests/framework/runtime/egress/test_docker.py` from the repository root. Evidence is `docker-test-evidence.json`, including image/source hashes and seven positive/negative control results. The test cleans only its UUID-named containers/networks. No host firewall changes, Docker socket mount, privileged containers or foreign-container mutations.

Topology: an actor with all capabilities dropped is attached only to an internal actor bridge. An explicit proxy is its only provider route. The proxy also joins a separate provider bridge, where the mock lives; the actor never joins that bridge. Production would give only the proxy an external provider route while keeping the actor bridge internal. The verifier runs `--network none`. Apply identical topology and allowlist to every arm, including None; changing HTTP_PROXY alone is insufficient because actors can unset it.

`EGRESS_ALLOWLIST` maps exact lower-case `hostname:port` authorities to trusted connection hostnames. Only configured destinations support HTTP forwarding or CONNECT. Numeric-IP requests and unknown destinations receive403. For production, populate reviewed provider/OAuth endpoints only; never wildcard arbitrary domains or approve hosts supplied by actors. The fixed mapping avoids actor-provided upstream destinations; production DNS resolution and IP-range checks remain to harden. Set HTTP_PROXY/HTTPS_PROXY/ALL_PROXY to the proxy and clear NO_PROXY for native clients; native clients' honoring those settings must be tested individually. Actor options must not grant NET_ADMIN, privileged mode, host networking, additional networks or Docker/socket access.

Controls cover allowed HTTP, allowed CONNECT establishment, denied mock public-test/solution URL, denied nonallowlist CONNECT, direct mock-provider IP, direct public IP and proxy numeric-IP CONNECT. Both provider and public-test endpoint are mocked. CONNECT positive proves tunnel establishment, not real TLS/provider authentication. Mock-provider direct access is blocked because it is on the separate bridge.

## Integration status and fidelity

Existing runtime `entrypoint.py` copies narrowly allowlisted auth artifacts into disposable HOME; this prototype does not import or log any credential files. Pi/Codex OAuth endpoint inventories and native agy OAuth/control-plane endpoints are **TBD**. Do not infer that api.openai.com alone suffices for ChatGPT OAuth, or that Gemini API endpoints suffice for agy. No production native actor is validated here. Preserve the selected native binaries/source hashes/model/effort and existing official verifier rather than replacing a native client with a mock HTTP actor in benchmark claims.

Required before real integration: reviewed endpoint inventory from local pinned client configuration/source; per-client proxy/TLS behavior; refresh/login endpoint policy; same-policy all-arm smoke test authorized separately; and an explicit rule that unknown required traffic blocks the run as infrastructure instead of silently enabling broad internet. No model call is authorized by this prototype.

## Limits

This is a destination allowlist, not semantic content filtering. A provider host can still serve arbitrary paths or tunneled traffic; CONNECT cannot inspect HTTPS paths without TLS interception. Public test/solution hosts are blocked, but malicious content hosted on an allowed provider origin or provider tools that themselves browse are outside this prototype's guarantee. Provider-side browsing/tools must be disabled or audited separately. Actors can contact the proxy service, but cannot add its provider network route. Production must additionally harden proxy resource limits, private-address/DNS policy, connection accounting and container lifecycle; the minimal proxy is not a production security gateway.

No request headers, authorization values, query strings or bodies are logged by the proxy. Saved evidence contains only source/image hashes and boolean mock results. This prototype establishes observed bypass controls in this Docker environment, not universal isolation against a kernel/container escape.

Native agy confirmation has a separate unresolved gate: its SDK exposes `search_web`/search tools that may retrieve tests/solutions on the provider side, outside local Docker egress. Root's inspected native help exposes no allow/deny-tool flag. `--agent`/`--sandbox`/permission options do not by themselves prove cloud browsing disabled. An audited cloud-tool policy or equivalent supported native configuration is required before claiming sealed native confirmation. Local network controls alone do not seal agy; this remains TBD and must not be bypassed by dropping native fidelity silently.

## Host gateway control

The actor bridge now uses `com.docker.network.bridge.gateway_mode_ipv4=isolated` with `--internal` and IPv6 disabled. Docker documents that ordinary internal bridges retain a host address, while isolated mode removes it: [Docker bridge isolation](https://docs.docker.com/engine/network/port-publishing/#gateway-modes). A temporary owned HTTP listener on the host is verified reachable from localhost, then direct access to the former bridge gateway address must fail (isolated mode has no assigned gateway). No existing host service is probed. Evidence records Docker version, gateway mode, IPv6 state and this eighth negative control. The earlier seven-control internal-only report is preserved separately. This improves the local prototype; native provider TLS/OAuth and cloud-side tool policies remain unverified.
