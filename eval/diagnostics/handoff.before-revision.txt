## Gotchas already solved (don't rediscover)

- **Effort:** the server's chat template rejects Claude Code's default effort `high` (HTTP 500), so every run uses `--effort medium`.
- **Skills don't auto-trigger** with this 27B model. Every arm's prompt ends with the same `SKILL_HINT` sentence
  (`eval/run_swe.py`) asking it to load installed skills; for baseline this does nothing. This is a declared limitation.
- **Host isolation:** fresh container and `HOME=/tmp/home` per run, so the host `~/.claude/CLAUDE.md` (which mandates
  karpathy-guidelines) and plugins never leak in. The Claude binary (2.1.285) is bind-mounted read-only from the host.
- **Patch hygiene:** `core.fileMode false` (otherwise every file shows a mode change), `.claude/` and `__pycache__/`
  excluded via `.git/info/exclude`. Stress repos need `chown root` or git refuses ("dubious ownership").
- **Harness version:** swebench 5.x needs a new dataset schema; use the pinned **4.1.0** in `eval/.venv` with `--namespace swebench`.
  All 49 sampled instance images are already pulled.
- **Tokens:** the server reports no cache fields, so input = full prompt per request. Report token traffic, not dollars.
- Runs ending in `error_max_turns` can still be resolved; resolution comes only from the grader.
